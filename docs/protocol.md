# Протокол тренировки, v1

Нормативный документ. Каталоги в `catalogs/` и схемы в `schema/` имеют приоритет
как машинная форма; настоящий документ описывает семантику, которую нельзя
выразить схемой.

## 1. Модель документа

Документ тренировки состоит из двух частей:

- `workout` — переносимое определение тренировки;
- `runtime` — настройки хоста, необязательные, не влияющие на семантику этапов.

Каноническое представление (`*.canonical.json`) получается нормализацией:

1. `duration_sec` → `duration_ms = floor(duration_sec * 1000 + 0.5)`.
2. Отсутствующий `stage_id` → `st-NN`, где `NN` — позиция с 1, ширина 2.
3. Значения по умолчанию проставляются явно.
4. Блок `runtime` удаляется.
5. Ключи объектов сортируются, JSON UTF-8, без BOM, `indent=2`, `\n`.

Нормализация идемпотентна: повторная нормализация канонического документа
не изменяет его.

Ограничения: `min_duration_ms` и `max_stages` зависят от профиля.

## 2. Разрешение политики пропуска

Итоговое разрешение `NEXT` для этапа вычисляется в порядке приоритета:

1. `stage.allow_skip`, если значение не `null`;
2. `runtime.commands.allow_next_on_manual` для `manual`;
3. `runtime.commands.allow_next_on_timed` для `timed`.

Значения по умолчанию: `timed` — разрешено, `manual` — запрещено.

Запрет приводит к `command.rejected` с `reason=skip_not_allowed`, этап continues.

## 3. Правила приёма команд

Команда отклоняется, если хотя бы одно условие нарушено (порядок проверок
нормативен и определяет `reason` при нескольких нарушениях):

1. `unknown_command` — имя не из каталога;
2. `not_supported` — команда не входит в `supported_commands` профиля;
3. `expired` — `age_ms > command_ttl_ms`;
4. `stale_context` — `context_stage_index` задан и не равен текущему индексу;
5. `low_confidence` — `source=voice` и `confidence < порога команды`;
6. `debounced` — та же команда от того же источника менее `debounce_ms` назад;
7. `invalid_state` — текущее состояние не в `allowed_states`;
8. `not_applicable` — `completion` этапа не в `applies_to_completion`;
9. `skip_not_allowed` — только для `NEXT`, по политике из п.2.

`STOP` проходит проверки 1–6, но игнорирует 7–9 в активных состояниях:
остановка должна быть доступна всегда, кроме терминальных состояний.

Принятая команда порождает `command.accepted`, затем события перехода.
Отклонённая — только `command.rejected`, состояние не меняется.

## 4. CONFIRM и NEXT

| | CONFIRM | NEXT |
|---|---|---|
| Смысл | этап фактически выполнен | этап пропущен |
| Область | только `manual` | `timed`, `manual` по политике |
| `stage.finished.reason` | `confirmed` | `skipped` |
| Учёт в статистике | выполнен | пропущен |

Синонимия запрещена на уровне контракта: голосовые фразы «готово» и «дальше»
отображаются в разные команды и не могут быть схлопнуты адаптером.

## 5. Порядок событий

Каноническая последовательность:

```text
workout.started
  (stage.started
     [stage.waiting_confirmation]        # manual
     [stage.countdown ...]               # timed
   stage.finished)*
workout.finished | workout.aborted
```

Инварианты:

- `seq` непрерывен и начинается с 1;
- ровно одно `stage.finished` на каждое `stage.started`;
- `stage.countdown` не более одного раза на целую секунду этапа;
- после терминального события публикация запрещена;
- обновления остатка времени не являются событиями.

## 6. Состояния и терминальность

`FINISHED`, `ABORTED`, `ERROR` терминальны. Повторный `START` в терминальном
состоянии отклоняется с `invalid_state`; перезапуск — новая сессия.

`PAUSED` объявлен, но в профилях `*-mvp`/`v1` не поддержан: `PAUSE` и `RESUME`
отклоняются с `not_supported`. Это фиксирует форму протокола, не требуя
реализации паузы.

## 7. Ошибки

Категории и коды — в `catalogs/errors.json`.

- `fatal` в конфигурации: тренировка не запускается, `error.raised` не
  публикуется, так как сессия ещё не создана; CLI возвращает `cli_exit`.
- `degraded` в аудио/голосе: публикуется `error.raised`, тренировка продолжается.
- `warning`: только лог и уведомление.

## 8. ViewState

`ViewState` — проекция состояния, единственная сущность, которую знает UI.
Требования:

- никаких строк, готовых к показу, кроме пользовательских имён из конфига;
  подсказки передаются ключом `hint_key`;
- `available_commands` вычисляется ядром по состоянию, политике и профилю;
  UI не должен сам решать, доступна ли команда;
- форматирование времени — обязанность адаптера, правило округления: `ceil`.

## 9. Граничные случаи, зафиксированные контрактом

| Случай | Поведение |
|---|---|
| `duration_ms` меньше окна отсчёта | отсчёт начинается с фактической целой секунды на старте этапа |
| Пропуск тактов из-за сна ОС | пропущенные `stage.countdown` не догоняются |
| Скачок времени больше `clock_jump_threshold_ms` | Публикуется `error.raised` с `RUN_002` и severity `warning`; пропущенные `stage.countdown` не догоняются; текущее наблюдение обрабатывается один раз; каскадный автопереход через несколько этапов запрещён |
| `CONFIRM` на таймерном этапе | `command.rejected`, `not_applicable` |
| `NEXT` на ручном этапе при запрете | `command.rejected`, `skip_not_allowed` |
| Голосовая команда после смены этапа | `command.rejected`, `stale_context` |
| Повторный `Enter` в течение debounce | `command.rejected`, `debounced` |
| EOF на stdin при ожидании подтверждения | `INPUT_002`, `workout.aborted` с `input_unavailable` |
| Ctrl+C | `STOP` от источника `keyboard`, `workout.aborted` |
| Последний этап завершён | `stage.finished`, затем `workout.finished` |
| Аудиоустройство недоступно | `AUDIO_001`, `degraded`, тренировка идёт без звука |

## Подтверждённые лимиты v1

| Параметр | desktop-mvp | android-v1 | esp32-v1 |
|---|---:|---:|---:|
| `min_duration_ms` | 100 | 100 | 1000 |
| `max_duration_ms` | 86400000 | 86400000 | 3600000 |
| `max_stages` | 512 | 512 | 128 |
| `max_countdown_seconds` | 10 | 10 | 10 |
| `tick_period_ms` | 100 | 100 | 200 |
| `clock_jump_threshold_ms` | 2000 | 2000 | 2000 |

Значения подтверждены как базовые для контрактов v1.

Изменение любого из этих значений считается изменением контракта и требует
обновления ADR, конформанс-векторов и версии пакета контрактов.

## Примечание

События `ExerciseStarted`, `RestStarted`, `TimerExpired`, `StageCompleted`
и `StageSkipped` из архитектурного документа v0.1 не являются частью
контракта v1. Они заменены событиями `stage.started` и `stage.finished`
согласно ADR-0003.
