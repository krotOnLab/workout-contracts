# Тайминги и обратный отсчёт

## 1. Часы

Единственный источник времени — монотонные часы. В Python `time.monotonic()`,
в Kotlin `System.nanoTime()`, в ESP-IDF `esp_timer_get_time()`.

Время в событиях (`t_ms`) — целые миллисекунды от старта сессии, не настенные.

## 2. Расчёт остатка

```text
deadline_ms = stage_start_ms + duration_ms
remaining_ms = max(0, deadline_ms - now_ms)
```

Запрещено накапливать время через `sleep(1)` и декремент счётчика.

Период наблюдения — `tick_period_ms` профиля. Реальная частота может быть ниже;
корректность определяется формулой, а не частотой.

## 3. Обратный отсчёт

На каждом наблюдении:

```text
s = ceil(remaining_ms / 1000)
если 1 <= s <= countdown_seconds и s не в emitted:
    опубликовать stage.countdown{second: s, remaining_ms}
    добавить s в emitted
```

Следствия:

- при `duration_ms = 3000` и `countdown_seconds = 5` первое событие — `s=3`
  на старте этапа;
- при `remaining_ms = 0` событие не публикуется, вместо него `stage.finished`;
- `emitted` сбрасывается на каждом этапе;
- при пропуске наблюдений публикуются только фактически наблюдённые секунды.

`countdown_seconds = 0` полностью отключает отсчёт.

## 4. Скачки времени

Если между наблюдениями прошло больше `clock_jump_threshold_ms`:

- публикуется `error.raised` с `RUN_002`, severity `warning`;
- пропущенные `stage.countdown` не восстанавливаются;
- если остаток истёк, публикуется ровно одно `stage.finished(timer_expired)`;
- каскадный автопереход через несколько этапов запрещён: за одно наблюдение
  завершается не более одного этапа.

Последнее правило защищает от «пробега» всей тренировки после выхода из сна.

Порядок публикации событий при обнаружении скачка времени нормативен:

1. Если между наблюдениями прошло больше `clock_jump_threshold_ms`,
   публикуется `error.raised` с payload:

   ```json
   {
     "code": "RUN_002",
     "category": "RUNTIME",
     "severity": "warning"
   }
   ```
2. Затем выполняется обычная обработка текущего наблюдения:
  - если остаток времени находится в окне обратного отсчёта,
    публикуется текущий `stage.countdown`;
  - если остаток времени истёк, публикуется ровно одно `stage.finished`
    с `reason=timer_expired`.
3. Прошедшие во время скачка секунды обратного отсчёта не восстанавливаются.
4. За одно наблюдение завершается не более одного этапа.

## 5. Пауза (зарезервировано)

При будущей реализации: `elapsed_ms` фиксируется, `deadline_ms` пересчитывается
при `RESUME` как `now_ms + (duration_ms - elapsed_ms)`. Снапшет хранит
`elapsed_ms`, а не абсолютные отметки времени.

## 6. Детерминизм в конформанс-тестах

В сценариях время дискретно: наблюдения происходят ровно на границах операций
`advance` и `command`. Реализация обязана воспроизвести ожидаемый набор и
порядок событий; сравнение `t_ms` выполняется только там, где оно указано
в ожидании.
